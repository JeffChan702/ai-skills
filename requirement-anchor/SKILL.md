# requirement-anchor — 需求锚定 12 格

## 它解决什么

拿到一段需求（一份原型稿、一段描述、几张截图），最怕的是**理解偏了**：做了一半才发现"这个字段其实不用做""这个入口在另一个页面""这个删除到底是不是物理删"。

这个 skill 用一张 12 格矩阵把需求边界锁死。每格必须给出**证据**和**验收判定**，填不满不许往下展开。

## 核心铁律

1. **任何需求 = 增删查改的变体。** 不存在脱离增删查改的业务需求。
2. **12 格是强制检查点。** 没填满，不许展开技术细节。
3. **一句话锚定就是边界。** 后续所有展开必须能回溯到那句锚点，禁止长出锚点之外的新实体。
4. **主依据是唯一事实来源。** 主依据里没有的页面、按钮、字段，矩阵里不得脑补。
5. **填不出来 = 证据不足。** 这时该回去要材料，而不是硬猜。

## 12 格矩阵

| | **增 Create** | **删 Delete** | **查 Read** | **改 Update** |
|---|---|---|---|---|
| **产品层** | 业务上新增什么？谁在什么场景触发？产生什么业务结果？ | 业务上废弃什么？物理删还是逻辑删？谁有权删？ | 业务上查看什么？给谁看？什么权限？看什么维度？ | 业务上修正什么？什么条件允许改？改后影响什么？ |
| **数据层** | 写哪张表 / 集合？主键策略？必填字段？关联写入？ | 删哪条记录？级联规则？软删标记？历史保留？ | 查哪几张表？关联条件？索引？过滤维度？排序？ | 改哪些字段？校验规则？并发控制？版本 / 审计？ |
| **展示层** | 入口在哪？表单 / 弹窗 / 导入？必填校验？提交反馈？ | 入口在哪？二次确认？批量还是单条？删除后状态？ | 列表 / 详情 / 卡片？筛选条件？分页 / 滚动？权限控制？ | 入口在哪？行内编辑还是详情页？哪些字段可编辑？变更提示？ |

## 每格怎么写

格式固定，四项并列：

```
主句一句话 ｜ 证据：具体依据 ｜ 验收判定：怎么算做对了 ｜ 可信度：🟢/🟡/🔴
```

- **主句一句话，禁止长篇**——但允许紧跟证据子项。
- **「—」是合法的**：某格确实无操作（比如一个纯开关需求没有"删"），可以填「—」，但**必须在边界声明里解释原因**。
- **每格必须有一个可断言的验收判定。** 它是留给实现完之后直接对照的检查点，专门用来减少「做完了才发现理解偏了」的返工。例如：
  - 「列表新增的列，在导出接口里也要返回」
  - 「删除后，该状态在其他页面同步隐藏」
  - 「改完之后，旧逻辑路径的数据保持不变」

### 三级可信度（每格必标其一）

| 标记 | 含义 | 后果 |
|---|---|---|
| 🟢 高可信 | 主依据有直接证据（原文 / 坐标 / 原型明确） | 可以直接转成实现项 |
| 🟡 需补充设计 | 原型没写，但可以推断（如表名、字段名、权限分级） | 标出推断来源，进「待确认清单」 |
| 🔴 领域知识补充 | 读不到，必须问人或读更多材料 | 标「待确认」，**置顶**提醒须人工知晓 |

**禁止脑补。** 主依据里没有的元素不许写进矩阵。如果用户口述里有、主依据里没有，标 `[主依据未体现，需补充设计]` 或 `[须读主设计稿 / 用户确认]`，而不是自己填一个看起来合理的答案。

## 展示层的入口必须三段式定位

```
所在页 → 所在区域 → 相对参照物（左右 / 上下 / 第 N 格）
```

缺任何一段 → 标 🔴 并注明需要确认。只写"在列表页"是不够的——那等于没说。

## 多图材料必须全看

如果主依据里含多张图（原型截图、多个方案稿、用户贴的补充截图），**每一张都要看过并留一行实质描述**，尤其是：

- 只看了第一张就下结论，是这类工作最常见的翻车方式
- 画面上同时出现「某个独立元素」+「同级区域的文字标签 / 分类」（比如"样式 1""方案 A"）→ 立刻假设两者是配对的，去比对全部图片确认
- 用户中途贴的补充截图，往往正好补上主依据里缺的那块证据，**别因为"我以为材料够了"就跳过**

留痕不能写"已读""见截图"这种空话，要写实质内容（界面布局、按钮文字、空态还是有内容、批注写了什么）。

## 边界声明（每层一句）

```
产品层边界：本功能不涉及……
数据层边界：本功能不处理……（「—」格的原因在这里解释）
展示层边界：本功能不展示……
```

## 偏离检测声明

> 后续讨论如果引入新概念（新页面 / 新表 / 新角色 / 12 格之外的新实体），必须先说明它填补了 12 格中的哪个空白；否则不许往下做设计。

这是防止需求越做越大的闸门。

## 工作流程

1. **复述锚点**：一句话复述需求。可以由主依据自动总结，不必强制用户口述。
2. **初填 12 格**：仅凭锚点 + 主依据里已提取的内容。合理推断标 `[推断]`。
3. **回填证据**：每格主句必须能回查到一条具体证据（原文引用 / 位置坐标 / 截图位置）。
4. **标可信度**：逐格 🟢 / 🟡 / 🔴。
5. **边界声明**：三层各一句。
6. **偏离检测**：写下那句声明。

## 什么时候可以跳过

- **主依据完全缺失**（连文字描述都没有）→ 先问 1~2 个关键问题，再回来填。
- **一行级的修复** → **仍然要填**，但只填本次实际涉及的格，其余格写「未涉及（本改动未触及）」。不要因为改动小就跳过锚定——小改动理解偏了照样返工。

## 边界

- 它只做「把需求结构化 + 标出不确定项」，**不判断需求本身合不合理**（那是评审的活）。
- 它对「纯口述、无任何材料」的需求帮助有限——那种情况该做的是先要材料，不是硬填。
