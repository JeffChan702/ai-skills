# trustworthy-ai · 让 AI 的产出可被信任

## 它解决什么

AI 的能力已经不是瓶颈了，**信任**才是。

- 它能写出能跑的代码，但你不敢直接合并
- 它能给出结论，但你不知道那是查出来的还是编的
- 它能"做完"一个任务，但你说不清它到底做了什么
- 长任务跑到一半它开始忘事，你却不知道从哪一刻起它的输出就不可靠了

这四个问题看着不一样，其实是同一件事：**它的输出是不可查的。**

这个 skill 给的是一个统一视角：

> **可信任不是"它说得对"，而是"它说的每句话都能被查"。**

以及——**一组你可以直接拿去问任何 AI 的四个问题。**

## 四条纪律，各管一头

| 什么时候 | 纪律 | 一句话 | 保证什么 |
|---|---|---|---|
| 做决定时 | **evidence-first** | 没依据的决定不许做 | **依据可查** |
| 改动代码时 | **blast-radius** | 爆炸半径最小 + 能归因 | **影响可查** |
| 交付时 | **false-done** | 产出存在不等于做完了 | **完成可查** |
| 长任务中 | **context-guard** | 上下文是工作台，不是硬盘 | **判断力不丢** |

## 万能四问（不用装任何东西就能用）

这是整个 skill 里最实用的一部分——**复制这四个问题，拿去问任何 AI**：

```
1. 你这个决定（结论）的依据是什么？来源在哪，我怎么自己复核一遍？

2. 这个改动会影响哪些地方？本来是对的那些地方，会不会被弄坏？
   如果上线后出问题，回退点在哪？

3. 你怎么知道它做完了？你实际执行了什么验证动作，
   看到了什么结果？哪些部分你没验证？

4. 你读进来的重要内容，写下来了吗？还是只在"脑子里"？
```

每一问都在逼它**说出一件具体的事**，而不是给你一个态度：

| 问题 | 逼出什么 |
|---|---|
| 1 | **依据的具体出处**——"惯例是这样"填不进那个格子 |
| 2 | **守恒项和回退点**——答不出回退点，说明对改动没有控制力 |
| 3 | **"做了"和"验证过"的区别**——要动作 + 结果，不要结论 |
| 4 | **把结论落在文件里**——压缩会丢记忆，文件不会 |

## 四条怎么配合：走一遍完整场景

假设你让 AI 做一个小需求，四条纪律分别在四个时刻介入：

| 时刻 | 用哪条 | 它会输出什么 |
|---|---|---|
| ① 它开始给方案 | **evidence-first** | 方案里带 `来源=推断（依据：xxx）`；说不出出处的被标成"待确认" |
| ② 准备动手改 | **blast-radius** | 改动计划：只动哪一条轴 + 守恒项清单 + 回退点 |
| ③ 它说"做完了" | **false-done** | 完成说明：至少两条"动作 + 结果" + 一节"没验证的部分" |
| ④ 任务跑了很久 | **context-guard** | 大文件不整读、压缩后不凭记忆重读、结论先写下来 |

**四步走完，你拿到的是一份"可以自己复核"的产出**，而不是一份"看起来没问题"的交付。

## 什么时候用它

- 你想给团队定一套"和 AI 协作的规矩"，但不想一上来就压四条细则
- 你只有一次机会问 AI，想知道该问什么（用万能四问）
- 你想快速判断"这次的交付能不能信"
- 你被"它说做完了但其实没有"坑过

## 怎么简单测试（1 分钟）

重启工具，发这段：

```
用 trustworthy-ai 的四条纪律检查这个交付：

我让 AI 帮我改了一个公共工具函数 formatPrice()，
它说「改完了，没问题」。我现在准备上线。
```

**通过标准**，它应该用四个维度分别追问：

- **依据**：为什么要改？改成什么样是谁定的？
- **影响**：这个函数被哪些地方用着？本来对的那些地方会不会坏？回退点在哪？
- **完成**：它实际验证了什么？只是改了代码，还是在页面上看过了？
- **记录**：改动前后的事实，有没有写下来？

而不是简单回一句"建议你测试一下"。

**失败信号**：如果它只给你一句笼统的建议（"注意测试覆盖"），那就是没装上——这套东西的特点恰恰是**具体到能执行**。

## 设计取舍

| 选择 | 原因 |
|---|---|
| **用"可查"作为统一标准** | 你没法判断 AI 聪不聪明，但你能判断一件事能不能自己核一遍。这是个可操作的标准 |
| **总纲 + 四细则，而不是一个大 skill** | 四条纪律发生在不同时刻、面向不同对象，塞进一个文件会互相稀释。索引的方式让每条都能讲透 |
| **把"万能四问"放最前面** | **方法应该先于工具。** 就算不装任何 skill，这四个问题也能立刻用起来 |
| **不提升能力，只暴露不确定** | 这个定位很重要：它不是让 AI 变强，是让它的不确定性变得可见——可见才谈得上管理 |

## 边界

- 它是**索引和视角**，不重复四条纪律的细节
- 它**不提升 AI 的能力**，也不保证它一定遵守。它给的是**可检查的问题**，让你在交付时能自己扫一遍
- 万能四问**对短任务显得啰嗦**。写段文案、问个知识点，用不上这些
- 它假设你**有复核的能力**。如果你完全无法判断回答对不对，这四个问题只能帮你把不确定性摊开，不能替你消除它
