# trustworthy-ai — 让 AI 的产出可被信任

## 它解决什么

AI 的能力已经不是瓶颈了，**信任**才是。

- 它能写出能跑的代码，但你不敢直接合并
- 它能给出结论，但你不知道那是查出来的还是编的
- 它能"做完"一个任务，但你说不清它到底做了什么
- 长任务跑到一半，它开始忘事，你却不知道从哪一刻起它的输出就不可靠了

这四个问题看着不一样，其实是同一件事：**它的输出是不可查的。**

## 一句话

> **可信任不是"它说得对"，而是"它说的每句话都能被查"。**

这个视角的好处是：你不需要判断 AI 聪不聪明，只需要问——**这件事我能不能自己去核一遍？**

## 四条纪律，各管一头

| 什么时候 | 纪律 | 一句话 | 它保证什么 |
|---|---|---|---|
| 做决定时 | **evidence-first** | 没依据的决定不许做 | **依据可查** |
| 改动代码时 | **blast-radius** | 爆炸半径最小 + 能归因 | **影响可查** |
| 交付时 | **false-done** | 产出存在不等于做完了 | **完成可查** |
| 长任务中 | **context-guard** | 上下文是工作台，不是硬盘 | **判断力不丢** |

四条各自独立，但指向同一个目标：**把"不可查"变成"可查"**。

## 万能四问（可以直接拿去问任何 AI）

这是这个 skill 最实用的一部分。**不需要装任何东西**，把这四个问题拿去问就行：

```
1. 你这个决定（结论）的依据是什么？来源在哪，我怎么自己复核一遍？

2. 这个改动会影响哪些地方？本来是对的那些地方，会不会被弄坏？
   如果上线后出问题，回退点在哪？

3. 你怎么知道它做完了？你实际执行了什么验证动作，
   看到了什么结果？哪些部分你没验证？

4. 你读进来的重要内容，写下来了吗？还是只在"脑子里"？
```

四个问题分别对应四条纪律：

| 问题 | 对应 | 它在逼出什么 |
|---|---|---|
| 1 | evidence-first | 逼它说出**依据的具体出处**（"惯例是这样"填不进这个格子） |
| 2 | blast-radius | 逼它说出**守恒项和回退点**（答不出回退点 = 对改动没有控制力） |
| 3 | false-done | 逼它区分**"做了"和"验证过"**（要动作 + 结果，不要结论） |
| 4 | context-guard | 逼它**把结论落在文件里**（因为压缩会丢记忆，文件不会） |

## 四条怎么配合：走一遍完整场景

假设你让 AI 做一个小需求。四条纪律分别在四个时刻介入：

**① 它开始给方案了** → 用 `evidence-first` 问：这个字段名哪来的？这个默认值是产品说的还是你推断的？
→ 输出的方案里会带 `来源=推断（依据：xxx）`，说不出来源的会被标成"待确认"。

**② 准备动手改了** → 用 `blast-radius` 问：基线是什么？这次只动哪条轴？守恒项写了吗？
→ 输出一份改动计划：明确"我只改这一条轴，其余不动"，以及"本来对的地方不许坏"的清单。

**③ 它说"做完了"** → 用 `false-done` 问：验证动作是什么？看到了什么？哪些没验证？
→ 输出一份完成说明，含至少两条"动作 + 结果"，以及一节"没验证的部分"。

**④ 这个任务跑了几十轮** → 用 `context-guard` 约束：大文件别整读、压缩后别凭记忆重读、结论先写下来。
→ 会话不会在中途崩掉，你也不会在某一步失去对它的判断。

**四步走完，你拿到的是一份"可以自己复核"的产出**——而不是一份"看起来没问题"的交付。

## 如果只装一个

看你的主要痛点：

| 你的痛点 | 装哪个 |
|---|---|
| 它老是自己乱定东西 | **evidence-first** |
| 它改一处坏三处、改坏了不知道从哪回退 | **blast-radius** |
| 它说做完了但其实是半成品 | **false-done** |
| 长任务跑到一半会话就崩/开始忘事 | **context-guard** |
| 说不清，都想要 | 四个都装，加这个总纲做索引 |

## 自检：这三件事出现了吗

- [ ] 它给的结论里，有没有**说不出出处**的？
- [ ] 它说的"做完了"，有没有**验证动作**支撑？
- [ ] 要改共享代码，有没有写**守恒项和回退点**？

任何一个答"没有"，就是该往回退一步、把纪律补上的时候。

## 边界

- 它是**索引和视角**，不重复四条纪律的细节——具体怎么做，看各自的 skill
- 它**不提升 AI 的能力**。它只做一件事：**让它的不确定性变得可见**
- **万能四问本身零门槛**。你不用装任何 skill，复制那四个问题去问就能用——这也是这个 skill 存在的意义之一：**先把方法给出去，工具只是顺手**。
