# three-cards — 三卡排查法

把任何故障拆成三道填空题。**前两张卡不需要懂任何内部原理**，只要把话说清楚、把边界定清楚。

## 什么时候用

- 有人给你一句模糊的故障描述（「XX 坏了」「用不了」），你不知道从哪下手
- 问题落在你不熟的领域，但你又想推进
- 想把手上零散的信息，整理成能交给别人、或交给别的 AI 的结构化材料

## 会怎么进行

**一次只推进一张卡**，填完整再往下一张。每轮结束输出"当前三卡状态 + 下一轮要问什么"，不一次性抛一堆问题。

### 卡一 · 问题模型（发生了什么）

| 字段 | 要求 |
|---|---|
| 动作 | 你做了什么（点 / 敲 / 按 / 发送 / 打开……） |
| 预期 | 你觉得应该发生什么 |
| 实际 | 实际上发生了什么 |
| 复现步骤 | 按顺序写，别人照着能做出一模一样的结果 |
| 约束 | 前提条件：特定时间 / 网络 / 账号 / 数据 / 设备 |

预期与实际的差距，就是「问题」本身。

### 卡二 · 环境与主体（发生在哪、在谁身上）

| 字段 | 要求 |
|---|---|
| 环境 | 版本 / 系统 / 设备 / 网络 / 时间 |
| 主体 | 涉及哪个对象：哪个账号 / 哪台机器 / 哪个订单 / 哪个人 |
| 已有 | 手上已经有的信息 |
| 缺失 | 还缺哪些（缺了才去要，不缺别乱要） |

### 卡三 · 机制与证据（为什么）

| 字段 | 要求 |
|---|---|
| 候选原因 | 可能的原因，按可能性从高到低排 |
| 支持证据 | 什么能证明它成立 |
| 反证 | 什么能一票否决它 |
| 下一步 | 成本最低的验证动作，做完能删掉至少一个候选 |

## 执行规则（硬，逐条遵守）

1. **一次只推进一张卡**，这张填完整再进下一张。
2. **卡一、卡二没填完整，不许跳到「为什么」。**
3. 用户描述里不确定的信息，**直接问，不要替他猜**。
4. 每个候选原因**必须带一条「能被验证或被否决」的证据路径**。写不出证据路径的原因，删掉——它不是原因，是玄学。
5. 拿到环境信息（设备旧、版本老、账号特殊）**不要当成根因**。环境用来缩小范围，不用来下结论。
6. **卡一填不出来 = 证据不足**。此时正确的动作是回去要材料，而不是开始猜原因。
7. 全程用大白话，不要甩黑话。

## 输出

每轮推进后输出：

```
【当前三卡】
卡一 · 问题模型：已填 / 待填（缺：xxx）
卡二 · 环境与主体：已填 / 待填（缺：xxx）
卡三 · 机制与证据：未开始

【下一轮要问】xxx
```

三卡填完后输出：

```
【卡一】现象 + 复现步骤 + 约束
【卡二】环境 + 主体 + 仍缺的信息
【卡三】候选原因（按概率排序）+ 每个的支持证据与反证
【下一步】成本最低的验证动作，以及它能排除掉哪个候选
```

## 边界

本 skill 只做「把问题结构化 + 决定下一步查什么」。

它**不代替专业判断**——卡三（机制与证据）仍然需要相应领域的知识。它能把外行带到「该找谁、该问什么」这一步，但不会让外行变成专家。
