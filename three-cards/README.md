# three-cards · 三卡排查法

## 它解决什么

排查问题一直是门玄学：老手问两句就定位，新手折腾一上午最后只能说"重启试试"。差别往往不在知识量——很多老手也不比你懂更多原理——**在于他们有一套看不见的流程**。

这个 skill 把那套流程写成了三张卡，任何人照着填就行。**前两张卡不需要懂任何内部原理**，只要把话说清楚、把边界定清楚。

| 卡 | 回答什么 | 门槛 |
|---|---|---|
| 卡一 · 问题模型 | 发生了什么？（**动作 → 结果**） | 零 |
| 卡二 · 环境与主体 | 发生在哪、在谁身上？ | 零 |
| 卡三 · 机制与证据 | 为什么？（候选原因 + 支持证据 + 反证 + 下一步） | 需要专业 |

核心是「动作 → 结果」这条主轴——它其实是「输入 → 处理 → 输出」的通用化，软件、电器、流程都一样成立。

## 什么时候用它

- 有人给你一句模糊的故障描述（"XX 坏了""用不了"），你不知道从哪下手
- 问题落在你不熟的领域，但你又想推进
- 想把零散信息整理成能交给别人（或交给别的 AI）的结构化材料

## 怎么装

把 `three-cards/SKILL.md` 复制到你的 skills 目录：

| 你在用的工具 | 目标路径 |
|---|---|
| Cursor | `~/.cursor/skills/three-cards/SKILL.md` |
| Claude Code | `~/.claude/skills/three-cards/SKILL.md` |
| WorkBuddy | `~/.workbuddy/skills/three-cards/SKILL.md` |

不需要装依赖。

## 怎么简单测试（30 秒）

重启工具，发这句：

```
用三卡排查：我的部署脚本今天开始报 permission denied
```

**通过标准**：它先反问你「执行了什么命令、预期什么、实际报什么错」，**一次只问一张卡**，而不是直接甩给你一堆可能原因。

如果它一上来就列了十条猜测，只有两种可能：目录名/文件名不对，或者工具没重启。

## 它不会做的事（硬规则）

- **一次只推进一张卡**，这张填完整再进下一张
- **卡一卡二没填完，不许跳到「为什么」**
- 你描述里不确定的信息，它**直接问**，不替你猜
- 每个候选原因**必须带一条「能被验证或被否决」的证据路径**；写不出证据路径的原因会被删掉——那不是原因，是玄学
- 拿到环境信息（设备旧、版本老、账号特殊）**不会当成根因**。环境用来缩小范围，不用来下结论

## 配合项目路径用（推荐）

```
用三卡排查这个问题：<一句话描述现象>

我的项目路径（卡三要读代码，可以填多个）：
- D:\code\my-app
- D:\code\my-shared-lib
- D:\code\deploy-scripts

要求：
1. 卡三的候选原因，要落到上面的代码里找支持证据和反证，不要凭空推断。
2. 读不到路径就直接告诉我，别猜。
3. 一次只问一张卡，卡一卡二填完再进卡三。
```

不给项目路径的话，卡三很容易退化成"猜"——允许 AI 读代码，才叫「带着假设去找证据」。

## 边界

卡三（机制与证据）**仍然需要相应领域的知识**。它能把外行带到「该找谁、该问什么」这一步，不会让外行变成专家。

另外，对**偶发、不可复现**的问题它会卡住——连"结果"都抓不住，就没有结果可写。
